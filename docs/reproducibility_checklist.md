# TAMM Reproducibility Checklist

Manuscript: **TAMM: Tail-aware Behavioral Motif-memory Mining for Open-world
Traffic Anomaly Diagnosis**

This checklist follows the ICDM 2026 Applied Track requirement that authors
complete a reproducibility checklist at submission time. ICDM links to the
Machine Learning Reproducibility Checklist v2.0 by Pineau et al. as the checklist
template. The structure below is organized as an outline so that reviewers can
map each paper result to data, code, commands, hardware, and known boundaries.

## 0. Path and Artifact Conventions

- Public code repository: `https://github.com/xxjuzxx/TAMM.git`.
- `repo:/...`: path relative to the cloned TAMM repository root.
- `artifact:/...`: path relative to the accompanying paper artifact package.
- The public GitHub snapshot contains code, configs, tests, selected runnable
  scripts, paper-facing aggregation wrappers, and adapted-baseline wrappers. It
  intentionally does not contain raw datasets, generated paper figures/tables,
  generated result CSVs, logs, model checkpoints, or large intermediate
  artifacts.
- Raw third-party PCAP datasets are not redistributed. The artifact package
  should include scripts, manifests, aggregate CSV/JSON summaries, and small
  smoke-test data where redistribution permits.

## 3. Method and Assumptions

### 3.1 Core Method Components

| Component | Reproduction detail |
|---|---|
| Behavior sequence | Flow events use direction, length-bin, inter-arrival-bin, burst, and transition/repetition evidence when available. |
| Motif transaction | Packet/burst items plus support-filtered profile and structural motif categories. |
| Histogram representation | Binary occurrence histograms with L2 normalization. |
| Benign memory | Exact cosine KNN over benign training memory, `k=3`, global benign memory. |
| Thresholding | Candidate thresholds use benign validation scores only. |
| Evidence records | Score, threshold, alert decision, active transaction items, nearest benign references, and contrast evidence. |
| P4-assisted split | P4 performs lightweight online preprocessing; host backend performs motif transaction construction, KNN scoring, thresholding, and evidence records. |

### 3.2 Mainline Setting

- Mainline result uses packet/burst transaction items, support-filtered profile
  and structural motifs, binary L2-normalized histograms, exact cosine KNN with
  `k=3`, and global benign memory.
- No attack-specific retuning is used for the headline leave-one-family result.
- Utility-selected motif dictionaries are compact audit views, not the headline
  result.
- EVT and empirical p-value thresholds are calibration tests, not
  distribution-free deployment guarantees.
- Memory update/compression rows are offline tests, not production SOC update
  policies.

### 3.3 Assumptions and Boundaries

- The unknown-attack proxy is a leave-one-family stress test.
- Held-out attack labels are used only for split construction and test
  reporting.
- Strong ranking separability does not imply stable benign-validation threshold
  calibration under benign-tail shift.
- External packet-artifact rows are portability diagnostics under available
  packet-level evidence, not universal cross-dataset generalization claims.
- The P4 testbed validates online preprocessing only; full TAMM scoring and
  evidence generation remain host-side.
- The system is not claimed as a production SOC deployment.

## 6. Split, Leakage, and Randomness Controls

### 6.1 Split Protocol

- Seeds: 42, 43, and 44.
- Benign training and benign validation rows are benign-only.
- Benign memory is fit from benign training rows only.
- Candidate thresholds use benign validation scores only.
- Held-out attack labels are used only for split construction and test
  reporting.
- Low-support attack classes are skipped rather than upsampled.
- Large-artifact split caps are pre-specified before evaluation.
- Aggregate rows use unweighted macro averages over family-seed runs unless
  otherwise stated.

### 6.2 Leakage Controls

| Control | Status |
|---|---|
| Train-only vocabulary and IDF | Enforced for reported artifacts. |
| Held-out attack excluded from benign memory | Enforced in leave-one unknown runs. |
| Held-out attack excluded from threshold calibration | Enforced. |
| Attack labels for motif fitting or utility selection | Prohibited. |
| Test-oracle thresholds | Separability metrics only. |
| Raw IP / absolute timestamp / five-tuple as behavior token | Prohibited. |
| Protocol/service as behavior token or memory key | Prohibited in behavior-only setting. |
| Payload bytes/application contents | Prohibited. |

### 6.3 Randomness

- Split construction records the seed in each split manifest.
- Exact KNN is deterministic once train/validation/test splits and transaction
  vocabularies are fixed.
- Coreset and update diagnostics use fixed seeds where sampling is involved.
- Aggregate rows should be regenerated from per-family/per-seed CSVs rather than
  manually edited.

## 7. Metrics

| Metric | Definition / role |
|---|---|
| AUROC, AUPRC | Ranking metrics. |
| FPR95 | False-positive rate at 95% attack recall. |
| Recall@0.1%FPR, Recall@1%FPR, Recall@5%FPR | Test-oracle separability metrics unless explicitly marked as benign-validation thresholding. |
| P99 FPR | Realized test FPR after applying benign-validation P99 threshold. Nominal 1% tail mass is not assumed to equal realized test FPR. |
| Macro-F1 and attack recall | Computed after applying the stated threshold for thresholded decisions. |
| FA/10k benign | Realized FPR multiplied by 10,000 benign flows. |
| Detected/10k attacks | Recall multiplied by 10,000 attack flows. |
| Precision at prevalence | Computed from reported recall and realized FPR under stated attack prevalence. |
| Batch ms/flow | Host-side batched exact-KNN latency; excludes capture buffering and flow-timeout waiting unless stated. |

## 10. P4-Assisted Online Testbed

- lightweight Ethernet/IP/TCP/UDP parsing;
- direction, length, and timing bins;
- simple per-flow counters/state;
- transition/repetition signals;

### 10.2 Host Responsibility

The host backend remains responsible for:

- burst reconstruction when needed;
- motif transaction construction;
- exact-KNN benign-memory scoring;
- thresholding;
- evidence-provenance record generation.

- export/digest/mirror setting;
- loss measurement method and raw log;
- resource utilization report;
- hash-collision and state-eviction measurement logs;
